## 2. Explanation of Changes

- **Stopping Port 8002:** The monitor printed WARNING for two rounds, then DOWN on the third round. This shows that the monitor requires 3 consecutive failures before confirming a service is down.
- **Restarting Port 8002:** The monitor returned to UP quickly after the service came back.
- **Making Port 8003 slow:** The monitor printed SLOW because the response time exceeded 500 ms.

## 3. Design Choices (Threshold & Timeout)

- **Timeout (1.0s):** I chose 1 second because a normal response takes a few milliseconds. Anything over 1 second is definitely unresponsive.
- **Fail threshold (3 checks):** I chose 3 consecutive failures so that a temporary network glitch doesn't immediately mark a healthy service as DOWN.
- **Gain/Loss:**
  - _Gain:_ Fewer false alarms (we avoid marking a service down due to a single dropped packet).
  - _Loss:_ It takes longer to detect a real failure (up to 3 rounds = 6 seconds).
